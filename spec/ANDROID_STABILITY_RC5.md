# RC5离线稳定性候选：未上机、未验收

用户反馈：关闭测试机自动USB路由、重插后，断续和失真明显减少，但仍偶发；
明确不能当作交付。之后手机低电量充电，暂缓真机/试听，不按等待时间推定充好。
手机仍为RC4。以下代码只在电脑检查，RC5没有安装到手机。

## 已定位并修正的数值问题

48k→384k异步重采样原来直接取256相位表中的较低相位。
时钟修正使相位在表格间移动，产生量化阶梯。
改成257个节点、相邻系数线性插值；保留64抽头、原滤波窗口和采样率。

合成正弦、137ppm时钟偏差，移除最佳拟合基波的增益/相位后测残差：

| 频率 | RC4残差 dBc | 修正后残差 dBc |
| --- | ---: | ---: |
| 997Hz | −76.64 | −120.80 |
| 10003Hz | −56.62 | −117.05 |
| 19001Hz | −51.04 | −104.53 |

这是离线数值误差，**不是耳机/声卡THD实测，也不是用户失真已消失的证明**。
测试信号未在设备播放。

## 其余修改仅用于排除故障/观察

- USB应用捕获前检查系统是否仍注册USB音频输出；
  如仍存在则要求先启用开发者选项“停用USB音频路由”并重插，避免重复争用。
  应用不会写受保护的系统设置；此前测试机修改通过已授权ADB完成，有原值备份。
- 记录USB回调最大间隔、超过现有12ms提交预算的次数、反馈拒绝数、
  反馈推算速率、线缆发送帧数及运行时间。
- 记录PCM饱和/非法样本、输入峰值、DSP保护计数。
- 记录AudioRecord读取帧数、缓冲大小、时间戳和零样本连续段。
  零样本可能只是暂停/静音；回调延迟也不等同已证明丢包，均须结合实听解释。
- **没有盲目加大USB排队深度、修改EQ或降低384k/32输出**。
  捕获输入仍48kHz float，不能把384k输出说成原音源满规格恢复。

## 已完成检查

- 4组正/负时钟偏差下的残差回归，要求小于−95dBc。
- 虚拟60秒变速时钟DC连续性、左右声道隔离、帧数边界、NaN时钟拒绝。
- 原WAV/DSF、升降采样、DSP五档采样率至384k检查。
- 原生8档采样率、正负漂移下虚拟一分钟包量、虚拟一小时包计数、
  反馈拒绝、PCM32/DoP打包。
- NDK原生库、APK编译、v3签名及16KB zipalign。

“虚拟一小时”是计算计数，**不是手机真实连续播放一小时**。
原有双声道/空间DSP未改，不重复宣称已完成新的声学测试。
