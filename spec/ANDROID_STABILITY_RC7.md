# RC7：按停止现场修USB故障与停止时序

## 已取得的现场

用户在RC6五分钟观察通过后又发生中断，同时报告停止按钮约半秒才停。
暂停测试充电期间，仅用同UID仪器导出已落盘报告，没有播放/采集。
报告：`evidence/rc6-interruption-stop-report.json`。

停止原因为`pipeline_error`，错误`USB isochronous packet failed/short`，
当次最后快照约601.7秒，USB欠载0、超64ms回调0，最大回调38.9ms。
这个具体停止不能解释成低内存杀进程或已证明的后台回收。
旧代码对任何端点的单个坏包都停止整条管线，且保存的是错误前快照，
因此同一报告会出现错误文本但`errors=0`。旧日志没有端点/状态/长度，不能猜是哪个端点。

## 修改

1. 分开处理反馈与音频输出。可恢复反馈短时失败会记录并继续，
   时钟超时仍受原1500ms门限限制；STALL/设备断开等不可恢复错误立即停止。
2. 仅PCM输出支持有界继续：最多连续3次、任意1秒窗口8次可恢复传输错误，
   超出上限停止。记录具体端点、包号、状态、期望长度、实际长度和恢复次数。
3. 失败PCM包对应的源帧单独保守计损，健康包单独确认完成；不重播整包，
   不把失败帧算作成功。EOF按完成+计损退役，避免因丢包永远无法排空。
4. DSD/DoP音频包出错不走PCM继续路径，立即停止，不能拿DSD位流冒险。
5. 停止请求主动唤醒libusb事件循环；阻塞的输入关闭移到停止线程，
   不在UI线程等待AudioRecord.stop。
6. 先等待USB I/O停止并保存新鲜原生状态，再关闭设备/恢复时钟。
   分别记录`stop_to_io_stopped_us`和`stop_to_release_ms`。
   UI区分“发送已停止”和“正在释放DAC”，不把资源清理延迟混成全部音频缓存。

这是故障控制与诊断修正，**不是恢复丢失音频**。有界继续可能仍有短瞬异常，
错误与计损不可藏成零。需要真机验证持续性与停止听感，不宣称已修好所有中断。

## 回归

`tests/UsbStreamFaultTest.cpp`在宿主机替换USB传输，通过真正的生产回调注入：
- 单个PCM短包只计损对应包，后续健康传输继续；
- 第四个连续故障停止；
- 反馈异常后可恢复，设备断开与DoP故障立即停止；
- 取消唤醒阻塞写者和事件等待。

`UsbAudioMathTest.cpp`检查恢复窗口上限、时钟/长时包量与PCM/DoP打包。
原Java DSP、SRC误差、变速连续性、音量与IO回归通过。
NDK及APK构建、签名与对齐通过。假传输不是USB硬件验收。

用户正充电，手机保留RC6，RC7未安装。没有继续进行手机播放测试。
下一轮需超过10分钟的实听，以及主动停止的I/O/释放耗时与用户听到的停止时间对照。
