# Android RC3：应用音频处理工作台

产品主流程调整为网易云/B站等应用 → 系统允许的播放捕获 → DSP → USB DAC。
不是本地播放器；打开/导入本地音频只保留为辅助诊断工具。

## 界面

- 默认进入“工作台”：音源、DAC、目标格式、开始/停止、输入/输出电平、链路计数。
- 音源选择：网易云音乐、哔哩哔哩、所有允许捕获的媒体应用。
- 主工作台和EQ页面均不要求选择本地文件。
- EQ、输出级、压缩器、矩阵和空间处理仍实时更新；A/B与撤销保留。
- “设备 → 诊断与本地辅助工具”保留本地/DSF/共享诊断和USB能力查询。

## 主流程

1. 连接DAC，选音源和USB输出，默认384000Hz/32-bit。
2. 点“开始处理”，按系统弹窗授权USB、录音权限和播放捕获。
   Android可能将最后一步显示为“屏幕共享”；应用只创建AudioRecord捕获，
   不创建VirtualDisplay、不读取屏幕内容、不写入录音文件。
3. 点“打开音源应用”或自行切过去播放。程序不会替用户选择或启动媒体内容。
4. 回到工作台，看输入电平是否出现，并核对实际USB格式与传输计数。
5. 参数调整实时生效。需要换音源/格式时先停止，停止后释放DAC并要求新的捕获授权。

## 来源范围与状态

指定网易云/B站时，将包名解析为当前用户的应用UID，使用addMatchingUid限定范围。
“所有允许的媒体应用”使用excludeUid排除OpenDSP自身。
不会混用UID包含和排除规则，不读取账号、播放历史或媒体目录。
Manifest只声明对这两个包的可见性，没有QUERY_ALL_PACKAGES。

状态区分为待机、等待授权、连接输出、缓冲、等待音源、正在处理、停止和错误。
仅服务启动或USB认领成功不能显示“已捕获声音”；输入RMS超过−90dBFS且已有传输
才进入“正在处理”。静音恢复有声时会更新状态，不保留旧静音提示。
RMS只汇总当前块的数值，不留存音频样本；输入和USB输出采样率分别显示。

待启动请求保存音源/格式快照，Activity重建时恢复同一请求；
取消/拒绝授权不会启动服务。正在运行时禁用来源及格式切换。

## 边界

这次完成产品类型、入口、来源过滤和状态反馈的改版，
不把它写成网易云/B站所有内容已经兼容。Android及播放器运行时捕获政策仍有效；
应用安装配置允许捕获，也不代表每次播放都允许。

捕获仍是复制，不会自动强制关闭原系统输出；此版本不自动修改手机媒体音量。
能否捕获到实际内容、是否双重输出、视频音画延迟、长时漂移和听感，需要后续实机协作测试。
当前捕获请求48kHz float输入，DSP与USB可运行384kHz/32-bit，
不能据此宣称网络音源被还原为原生384k高解析。

APK：`dist/OpenDSP-Android-0.4-apps-rc3.apk`，code7，沿用原包名和开发证书。
原USB RC2静音链路验收与接口认领修复继续保留。
