# OpenEQ 架构与验收边界

## 交互

最上方始终显示 USB 独占输出开关、目标设备和实际状态。开关下方为均衡 / 预设 / 设备。主页保留总开关、曲线和滤波器列表；输出与声道、高级参数使用独立编辑面板。所有数值支持直接输入和 0.1 步进。

后续独占状态机：不可用 → 等待权限 → 打开中 → 独占已确认 → 释放中 / 故障。只有后端打开成功且格式确认后，才能显示独占已确认。设备拔出时及时失效，禁止无提示地切换到手机扬声器。

## Android 免 Root

完整自研 DSP 作用于 OpenEQ 能取得的 PCM 音频。其他应用通过系统 AudioEffect 的受限后端适配，必须显示实际支持的频段与功能，不用近似滤波伪装完整 PEQ。系统 AudioPlaybackCapture 不承担全局覆盖承诺。

## Android Root

需分开实现并验证：

1. 音频入口：路由 / 系统混音接入，诊断录音权限、厂商音频策略和硬件 offload。
2. DSP：无音频线程文件 I/O，配置原子切换、交叉淡化、PCM 格式与声道管理。
3. USB：设备描述符解析、UAC 版本、时钟、端点、同步反馈、缓冲与热插拔。
4. 生命周期：Root 服务按需运行、故障时释放设备、恢复路由；临时 AudioPolicy 必须注销；当前不安装 Magisk 音频模块。

直接打开 REMOTE_SUBMIX 的早期探针全零；注册临时 AudioPolicy 后，媒体与游戏捕获、完整 PEQ、后台前台服务、实时参数切换和注销恢复已通过 Z Flip5 真机测试。Root 输出目前使用 AudioTrack 共享路径，不是 USB 直出。策略按 usage 捕获媒体/游戏并排除 Root 输出 UID，避免重复捕获。停止使用临时 stop 文件、父进程存活检查与 AudioPolicy 注销；新旧会话不得重叠。

Android USB Host 公共 Java API 没有直接提供完整的等时 USB 音频驱动。后续需要合适的 native USB 或 ALSA 后端，不能把 `AudioTrack.setPreferredDevice()` 叫做 USB 独占。Root 本身也不证明成功打开了物理 USB 音频端点。

## Windows

应用 → 虚拟播放端点 → 接收 / 混音 → DSP → WASAPI exclusive → USB DAC。

优先验证 WASAPI 输出端和 DSP，再实现虚拟音频驱动。正式发布解决签名、安装、卸载、升级与断线恢复。显式选择其他物理输出或直接 ASIO 的应用不能假定自动被接入。受保护音频不承诺可捕获。

## 端到端验收

浏览器与音乐应用同时播放不同测试信号；确认输出仅经 OpenEQ，旁路及 EQ 响应可测。确认 USB 独占成功并用第二客户端竞争验证；测量 DSP 前后响应，不用 DAC 屏幕显示代替测量。至少进行热插拔、锁屏、前后台、重启、不同采样率并发及一小时连续播放测试。Android 与 Windows 同配置的离线测试向量应达到约定误差。当前仅通过 README 列出的初始检查。

## Windows 0.3 路由补充

Windows 原生麦克风侦听目标在独占打开之前改到虚拟入口。目标属性变更后短暂重新建立已启用的原生侦听流，保持最终启用状态；仅改属性但不重新建流在本机可出现无声。停止后恢复原目标。复测同时检查麦克风共享采集、入口信号及关闭侦听后会话消失，不能只以复选框读回值作为成功依据。该属性键与 PolicyConfig 属于 Windows 非公开兼容接口，需要在新系统版本回归。

蓝牙使用 WASAPI 共享模式，自研 DSP 不变。JSON 配置物理参数可共享；系统原生固定频段的 Android 兼容设置单独保存，不伪装成任意 PEQ。

## PC 音质基线与原生路径

当前中转模式并非整条原生链路：系统共享混音到虚拟端点，再由回环采集和独立时钟校正重采样送往物理设备。WASAPI 独占仅证明最后一段的设备所有权；输出显示 384 kHz 不能恢复入口之前已丢失的信息，也不能证明音质优于系统共享输出。

后续原生系统 EQ 应采用物理端点的 APO 插入 DSP，不建立第二个虚拟端点或回环重采样链路，保留 Windows 选择的原生设备混音格式。这是共享音频路径，不能标为 USB 独占。ASIO、WASAPI 独占或主动绕过效果的播放路径必须单独支持，不能承诺全部捕获。不同源采样率同时混音仍需统一输出时钟。

2026-10-17 增加 ASRC 全频段正弦投影测量。旧 64 taps / 32 phases 在 48→96 kHz、20 kHz 信号下残留约 −44.08 dB；256 / 256 为 −114.13 dB。残留含超声镜像，不等于可听失真，也未定位用户听感下降的全部原因。改参数不能替代对原生系统路径的支持或声学验收。

## Windows 0.4 原生 APO 实现

`windows/OpenEQ.Apo` 是独立 MIT C++ 实现，使用 Windows SDK 的 COM / APO 接口，支持 COM 聚合。物理设备绑定为 MFX，在 Windows 模式混音路径中处理浮点 PCM；没有 OpenEQ 回环、虚拟播放设备或重采样器。EFX 单独绑定未在本机生效，MFX 的真实 AudioDG 执行已验证。

参数通过 4096-byte 映射文件发布：有界 seqlock 快照、32 段滤波器、完整输出声道设置。音频回调不做文件 I/O 或动态分配，双 bank 做 20 ms 交叉淡化；延时缓存在 LockForProcess 分配。各音频模式实例共用设备配置，遥测使用原子聚合。心跳八秒过期后自动旁路，不依赖主 UI 存活。55 项 native 接口/DSP 检查与真实 AudioDG 进程终止恢复通过；不等于完成 HLK 或正式签名认证。

设备原始 MFX/EFX 属性与 Disable_SysFx 属性保存在 ProgramData/OpenEQ/apo 的备份中。未签名开发 APO 需要用户明确允许 DisableProtectedAudioDG；原值独立备份，恢复动作可撤销此设置。已有第三方 MFX 时拒绝覆盖。安装/升级写入按内容 hash 命名的 DLL，并刷新音频服务以避免 COM 类工厂缓存继续使用旧代码。
