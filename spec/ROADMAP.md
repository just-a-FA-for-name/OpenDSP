# OpenDSP 路线图 —— 开源 HiFi DSP 套件

定位（用户定调，2026-10-17）：**不是单点 EQ，而是完整的 DSP 套件、真正的 HiFi 软件，目标是开源 HiFi 软件里的标杆。集百家之长，但必须做扎实。Windows 先完成，之后再做安卓。**

## 已完成（0.4 核心，均有实测证据）

- 32 段参数 EQ / 7 类滤波 / 左右声道 / 0.1 dB 步进 / 曲线编辑 / A/B / 撤销 / 通用 JSON。
- 输出级：增益、平衡、左右延时、反相、峰值保护（sample-peak，待升级 true-peak）。
- 原生 APO 共享链（AudioDG 内浮点处理，TEARDSP 实测 384 kHz 满血运行）。
- 独占链路：设备所有权严格证明 + **同率零转换直通** + 目标采样率可满血 384k（TEARDSP 实测 −41.995/−30.000 dB 传递精确）。
- 设备识别/预设绑定、采样率同步（96k 真实同步+恢复验收）、系统“侦听此设备”兼容（TEARDSP 真机全绿）。
- 虚拟声卡驱动 OpenEQ.VirtualCable 构建链（WDK NuGet 无管理员构建、测试签名产物）。

## DSD 输出模式（2026-10-17 夜，核心差异化）

**目标**：USB 独占链路支持 DSD 直出（DoP），让 DAC 真正跑在 DSD 模式——市面上付费工具才有的能力，OpenDSP 开源做到。

- **已实现并离线全绿**：16× 多相插值 → 5 阶误差反馈 Σ-Δ 调制（运行时 NTF 设计，‖NTF‖∞=1.45 满足 Lee 判据；TPDF 抖动只影响判决、误差被 NTF 整形）→ DoP 成帧（0x05/0xFA 标记，dCS 标准布局）。
- **实测**（`evidence/suite-dsd.json`）：DSD64/DoP 176.4k 带内 SNR **86.2 dB**，DSD128/DoP 352.8k **94.1 dB**；带外/带内差 95–103 dB；成帧、稳定性、幅度保持（<0.001 dB）全绿。
- UI：输出处理对话框新增「DSD 输出模式：PCM / DSD64·DoP / DSD128·DoP」，独占链路生效；需 DAC 支持 DoP。
- 边界（诚实声明）：PCM→DSD 是调制转换（非 bit-perfect）；DSD 源文件的透传播放列入下一阶段（DSF/DFF 解析 + DoP 直通 = 真 bit-perfect DSD）。
- **许可纪律**：核心调制器为自研实现（Schreier/Lee 教科书方法学）；调研参考过无许可项目仅读思路未取代码。开源发布前完成第三方清单（`THIRD_PARTY.md`）。

## 耳机一对一调音（核心服务化能力，2026-10-17 定义）

原则（用户定调）：**目标曲线只是方向与起点，每副耳机听感不同，必须针对具体耳机一对一微调**，最终形成该耳机专属的调音（设备预设自动绑定）。

工作流（AI 引导的一对一调音）：
1. 建档：确认耳机型号/佩戴（当前：SGOR LUNA 平板振膜、两头翘）。有测量 CSV 则导入（调音卡片入口），无测量则从目标曲线起点生成。
2. 听感对齐：用户听参考曲目，描述想要接近的听感（如“人声更近”“低频收紧不轰”“齿音柔化”）；AI 逐轮改具体频段（频率/增益/0.1dB/ Q）并说明改动。
3. A/B 复核：对比前后与目标曲线叠加（EQ 图橙色虚线），保留/撤销；确认后保存为该耳机专属调音（按设备自动记忆，换耳机自动切回）。
4. 迭代固化：长期微调痕迹保留；不同音量下复核（配合低音量补偿曲线）。
5. UI 支撑（下一阶段）：耳机档案页（型号/测量/听感偏好/调音历史）、目标曲线偏移滑杆（低频/中频/高频整体倾向）、听感标签快速预设。

分工：生成与迭代由 AI 完成；最终听感由用户耳朵判定（数字测量只作辅助）。
