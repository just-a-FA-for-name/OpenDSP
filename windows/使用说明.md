# OpenDSP Windows 0.4（原生 APO）

幻音 4X 曾出现连续"哒哒"声，撤回并重启后恢复。当前固定 48 kHz / 32-bit 的原生 APO 已通过网易云真实音乐音量对比和低架滤波器实听，界面正在处理音乐。高采样率及频繁格式切换导致异常的完整根因、长期稳定性尚未关闭，当前是候选试用版本。

运行 `OpenDSP.exe`，保留同目录 `OpenEQ.Apo.dll` 和许可文件。默认启用"原生系统 EQ"，音频入口显示"Windows 原生音频路径"，不需要虚拟声卡。

## ⚠️ 384 kHz 不是所有应用都吃得下

**有些应用，特别是游戏，在 384 kHz 输出格式下会没声音、爆音、卡顿或报设备错误。把它切到 192 kHz 就能正常使用。**

在「设备」页把 **采样率** 选成 `192000`（或输入 `192000` 后回车让程序查询驱动），位深保持 `32-bit`，点 **「同步到系统」**，然后**重开那个游戏或应用**。开着「USB 独占」时不能同步系统格式，先关掉；其他程序正在放声音时软件会拒绝改格式；切换会短暂断音；原有格式会自动备份，可在「更多」菜单恢复。也可走 Windows 设置 → 声音 → 输出设备属性 → 高级 → 默认格式。

192 kHz 仍是 44.1 / 48 kHz 音源的四倍，EQ 系数按实际处理采样率重算，功能一点不少。这只是兼容性开关，不是性能档位。该建议来自实际使用经验，没有逐款游戏做过兼容性矩阵。

## 使用步骤

1. 选择物理 USB 声卡或耳机，点击"开始处理"。首次安装、升级 APO 或绑定新设备会出现 Windows 管理员提示。
2. 开发组件尚未签名。首次允许未签名 APO 前会说明对受保护音频的影响；原设置会备份。正式签名与整夜稳定性验收未完成。
3. "系统格式"直接设置 Windows 物理端点的采样率和位深，列表由驱动查询获得。原生 APO 按实际处理采样率运行；不建立 OpenEQ 重采样链路。Windows 仍负责应用格式不同所需的转换和共享混音。
4. 曲线节点、频率、增益、Q 与输出设置均实时应用；数值可直接输入，± 为 0.1。原生 DSP 与 Windows / Android 通用 JSON 配置一致。曲线按当前处理采样率显示。
5. 预设菜单可选择工厂预设、保存或重命名、自定义设备绑定。保留 A/B 槽、撤销、APO 参数导入、导出与输出声道处理。
6. "麦克风侦听"对应真正的 Windows"侦听此设备"。原生模式不把麦克风改到虚拟入口；TEARDSP 的原生监听与共享录音已在 384 kHz 路径实测。
7. 停止处理会旁路原生 EQ，并恢复由 OpenEQ 改过的默认设备。关闭窗口默认保留托盘；从托盘退出才停止。控制进程异常终止后，原生 DSP 在心跳约八秒过期后自动旁路，Windows 声音继续。
8. 更多菜单可恢复当前设备原来的系统音效绑定，或恢复安装前的 Windows 音频保护策略。恢复音频保护会使未签名 APO 不能再加载。

开发修复：系统格式变更前会持久保存设备 PCM 与混音格式，切换后分别回读位深与采样率；更多菜单可按备份恢复修改前格式。切换后保持停止处理，先确认直出正常。其他应用仍在播放，或设备/USB 上级设备待重启时，拒绝修改格式。无备份时不猜测原始格式，检测到其他程序改过格式时不静默覆盖。本轮通过 18 项故障及共享文件检查，真实格式变更恢复仍待验收。首次安装、升级或卸载开发版 APO 会重启音频服务、短暂中断播放，需要等播放器恢复后再验证声音。

原生模式是系统共享 EQ，不是 USB 独占。ASIO、WASAPI 独占、绕过音效和受保护内容不保证处理。已有其他模式 APO 的设备暂不覆盖，需要适配串联；新后端的蓝牙实机验证尚未完成。

可选中转独占：关闭"原生系统 EQ"，选择已有虚拟音频入口，再打开顶部 USB 独占。此时才使用回环、时钟校正重采样和临时麦克风监听重定向。独占是最后输出段的访问方式，并不自动证明整条链路音质更好。

新建平直预设的软件增益为 0 dB，已有自定义衰减会保留。sample-peak 保护不是 true-peak 限幅器；需要比较完整原声音量时也应检查保护、前级、输出增益与系统音量。原生麦克风侦听仍有 Windows 路径延迟，不是硬件零延迟返听。
